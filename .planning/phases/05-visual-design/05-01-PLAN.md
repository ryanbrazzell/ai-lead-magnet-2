  <action>
Execute a structured adversarial design process with three named perspectives. This is a DESIGN PROCESS, not code implementation. The output is a DESIGN-DECISIONS.md document.

**Step 1: Read the current design state.**
Read `web/src/lib/pdf/layout-v2.ts` to understand every current visual parameter: the COLORS object (hex values), font sizes used across all renderers, spacing values, section header treatments, CTA button styling, task card styling, and footer/header patterns. Also read `web/src/lib/pdf/design-system.ts` for V1-era brand colors and `web/src/app/globals.css` for the web brand palette (Navy #0f172a, Gold #f59e0b, Green #10b981).

**Step 2: For each of the 8 design dimensions below, run the adversarial process.**

The 8 dimensions (from 05-RESEARCH.md):
1. Core Four Accent Color Palette (current placeholders: blue, purple, amber, green)
2. CTA Button Color (current: teal #0D7377)
3. Cover Page Emotional Treatment (financial pain emphasis)
4. Framework Page Visual Treatment (trust/education aesthetic)
5. Task Page Density and Visual Rhythm (overwhelm effect)
6. CTA Page Openness (relief/action clarity)
7. Typography Weight Distribution (bold/normal patterns per page)
8. Footer and Running Header Treatment

**For EACH dimension, write all four rounds into the document:**

**Round 1 - Proposals (each perspective proposes):**

Perspective A (Marketing Impact Advocate):
- Values: conversion, urgency, visual hierarchy driving eye to CTAs, color psychology
- Optimizes for: "Does this make the reader more likely to book the Time Audit call?"
- Tendency: bolder colors, larger CTAs, more contrast, urgency signals

Perspective B (Visual Simplicity Advocate):
- Values: white space, restraint, readability, premium consulting feel, "less is more"
- Optimizes for: "Does this feel like a premium consulting deliverable?"
- Tendency: fewer colors, more white space, cleaner typography, removing decoration

Perspective C (Information Density Advocate):
- Values: scanability, visual structure, information hierarchy, pattern recognition
- Optimizes for: "Can the reader absorb maximum information with minimum cognitive load?"
- Tendency: structured grids, consistent visual rhythms, color-coding, clear delineation

Each proposal MUST include:
- Specific RGB tuples (not just color names)
- Specific mm/pt measurements where relevant
- The jsPDF method that renders it (e.g., `doc.rect()`, `doc.setFillColor()`)
- If a proposal cannot name the specific `doc.xxx()` call, it is INVALID -- reject it

**Round 2 - Critiques (each perspective critiques the other two):**
Each perspective identifies specific weaknesses in the other two proposals. Critiques must reference the business goal (driving Time Audit bookings) and jsPDF constraints.

**Round 3 - Synthesis (select winner per dimension):**
For each dimension, select the winning approach by evaluating against these criteria (in priority order):
1. Conversion effectiveness -- does this make the reader more likely to book?
2. jsPDF feasibility -- can this be implemented with available primitives?
3. Brand coherence -- does this feel like Assistant Launch?
4. Emotional arc integrity -- does this support the correct emotional tone for its page position?
5. Implementation simplicity -- simpler code changes preferred

Marketing Impact Advocate carries tiebreaker weight when the other two are evenly matched (the PDF exists to drive conversion, not to win design awards).

**Document each final decision in this format:**

```
### [Dimension Number]. [Design Dimension Name]

#### Proposals
**Marketing Impact:** [specific proposal with values]
**Visual Simplicity:** [specific proposal with values]
**Information Density:** [specific proposal with values]

#### Critiques
**Marketing critiques Simplicity:** [specific objection]
**Marketing critiques Density:** [specific objection]
**Simplicity critiques Marketing:** [specific objection]
**Simplicity critiques Density:** [specific objection]
**Density critiques Marketing:** [specific objection]
**Density critiques Simplicity:** [specific objection]

#### Decision
**Winner:** [specific choice with exact values]
**Values:** [exact RGB tuples as [R, G, B], mm measurements, pt sizes]
**Rationale:** [why this wins -- which criteria decided it]
**Championed by:** [which perspective(s)]
**Concessions:** [what the losing perspectives conceded and why]
**Code target:** [specific function/constant in layout-v2.ts to modify]
```

**CRITICAL CONSTRAINTS for all proposals:**
- jsPDF has NO gradients, NO shadows, NO transparency, NO custom fonts, NO SVG icons, NO dashed lines, NO background images
- Every visual effect must use: `doc.rect()`, `doc.roundedRect()`, `doc.circle()`, `doc.line()`, `doc.text()`, `doc.setFillColor()`, `doc.setTextColor()`, `doc.setDrawColor()`, `doc.setFontSize()`, `doc.setFont('helvetica', ...)`
- Core Four accents must be distinguishable from each other AND from background/text colors
- The existing font size hierarchy (56, 26, 24, 22, 18, 14, 13, 12, 11, 10, 9, 8 pt) should be respected -- new sizes only if none of the existing ones work
- Any spacing change must account for Y-budget constraints (framework page has ~21mm buffer in stacked layout)

**For Dimension 1 (Core Four Accent Colors) specifically:**
- Each accent needs THREE variants: (a) full accent for header fills, (b) light variant (~95% lightness) for card backgrounds, (c) text-safe version for labels
- Must span different hue positions (not four shades of the same hue)
- Must be distinguishable in grayscale
- Consider whether to derive from brand palette (Navy/Gold/Green/Teal) or use a broader spectrum

**Step 3: Write the final DESIGN-DECISIONS.md file.**
Include:
- Header with date and process summary
- All 8 dimension decisions in the format above
- A consolidated "Implementation Cheat Sheet" at the end that lists every C constant change, every spacing change, and every renderer modification as a flat list for easy reference by Plan 05-02
